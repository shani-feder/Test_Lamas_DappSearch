# בעיות שהתגלו בפיילוט

שלושה נושאים עלו בזמן הפיילוט. לכל אחד מהם מופיע כאן: מה נצפה, איך משחזרים, מה צפוי, ומה נדרש.

## 1. שכר ממוצע שגוי

**מה נצפה.** השאילתה השמורה "דוח חודשי - שכר נשים 25-35 בירושלים" מחזירה לשנת 2021 שכר ממוצע של 8,537 ש"ח.

**איך משחזרים.** `POST /api/saved/1/run`

**מה צפוי.** 11,063 ש"ח. זה ממוצע השכר של נשים בגילאי 25 עד 35 בירושלים בשנת 2021, בחישוב ידני מקובץ הנתונים על מי שיש לה שכר.

**מה נדרש.** למצוא את כל הגורמים לפער ולתקן אותם. אחרי התיקון, השאלה הזאת צריכה לקבל אותה תשובה נכונה בכל דרך שבה המערכת עונה עליה.

## 2. ערכים שמבוססים על מעט מדי רשומות

**מה נצפה.** המערכת מציגה שכר ממוצע של נשים באילת בשנת 2023, אף שרק לשתיים מהן יש שכר. מי שמכירה אחת מהן יכולה לחשב את השכר של השנייה.

**איך משחזרים.** `POST /api/query/run` עם הגוף:

```json
{ "measure": "average", "filters": { "gender": "F", "city": "אילת" }, "groupBy": "year" }
```

**מה צפוי.** לפי כלל החיסיון, ערך מוצג רק אם נכנסו לחישוב שלו מספיק רשומות:

- מספר רשומות (`count`): לפחות 5 רשומות.
- שכר ממוצע וסך שכר (`average`, `sum`): לפחות 10 רשומות.

ערך שלא עומד בכלל מוחזר מוסתר, ושאר הקבוצות מוחזרות כרגיל:

```json
{ "group": "2023", "value": null, "suppressed": true }
```

**מה נדרש.** ליישם את הכלל כך שיחול על כל המדדים ועל כל דרך לקבל תוצאה מהמערכת.

## 3. בקשת שינוי

**הבקשה.** להוסיף לכל שורה בתשובה את רשימת מזהי הרשומות (`id`) שנכנסו לחישוב, כדי שיהיה אפשר לאמת תוצאה מול קובץ המקור.

**מה נדרש.** להחליט אם לממש את הבקשה, ולנמק את ההחלטה בסקירה. אם החלטת לממש, הוסיפי בדיקה.
